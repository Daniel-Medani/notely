## Spacing Scale

Declared values (multiples of 4, 8-point base scale):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding between icon and text |
| sm | 8px | Compact element spacing, input internal padding vertical |
| md | 16px | Default element spacing, card padding, form field gaps |
| lg | 24px | Section padding, card-to-card gaps |
| xl | 32px | Auth card max internal padding, layout section gaps |
| 2xl | 48px | Vertical centering offset for auth card |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Touch targets (sidebar toggle button, user avatar button): minimum 44px × 44px — exceeds 8-point grid to meet WCAG 2.5.5 Target Size
- "or" divider spacing: 16px vertical margin above and below the `<Separator>` element

**Source:** default 8-point scale; touch target exception is discretion default per WCAG

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.15 |

**Declared weights: 2 total — 400 (regular) and 600 (semibold).**

**Notes:**
- Body (14px/400/1.5) is used for: form input placeholder text, helper text, error messages, sidebar nav items, empty state body copy
- Label (14px/600/1.4) is used for: form field labels, section headers in sidebar ("Pages")
- Heading (20px/600/1.2) is used for: auth card title ("Sign in to Notely", "Create your account"), workspace empty-state heading ("Welcome to Notely")
- Display (28px/600/1.15) is used for: "Notely" brand text in auth pages only (D-04)
- Font family: Inter via `next/font/google` loaded in root layout, set as `--font-sans` CSS variable

**Source:** Claude's Discretion (CONTEXT.md); shadcn/ui new-york defaults inform sizing

## Color

Tailwind v4 uses OKLCH CSS variables defined in `globals.css` via `@theme`. The following maps to shadcn/ui's semantic token system.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (white in light / near-black in dark) | Page background, auth page background, workspace main area |
| Secondary (30%) | `--card` / `--muted` (off-white in light / dark surface in dark) | Auth card surface, sidebar background, input background |
| Accent (10%) | `--primary` (neutral-900 in light / white in dark) | Reserved for specific elements — see list below |
| Destructive | `--destructive` (red-600 approx) | Destructive actions and error states only |

Accent (`--primary`) reserved for:
1. Submit buttons ("Sign in", "Create account", "Continue with Google") — filled variant
2. "New Page" CTA button in the empty workspace state (D-10)
3. Focus ring on interactive elements (keyboard navigation indicator)

**Accent is NOT used for:** sidebar nav items, section headers, dividers, labels, helper text, card borders.

Error text (D-13) uses `--destructive` at full opacity — rendered with `text-destructive` class directly below the field.

**Source:** CONTEXT.md D-13 (red inline errors); D-10 (New Page CTA); shadcn/ui new-york semantic token defaults

## Layout Contracts

### Auth Pages (`/login`, `/register`) — D-02

- Viewport: full-height flex column, `items-center justify-center`, `min-h-screen`
- Background: `bg-background`
- Card: `w-full max-w-sm` (384px), `p-8` internal padding
- Card structure top-to-bottom:
  1. Brand text "Notely" — Display typography, centered, `mb-8`
  2. Page title ("Sign in to Notely" or "Create your account") — Heading typography, centered, `mb-6`
  3. Google OAuth button — full-width, outline variant, `mb-4`, leads with Google icon from lucide-react (D-03)
  4. `<Separator>` with "or" label centered — `my-4`
  5. Form fields stacked with 16px gap between each field group (label + input + error)
  6. Submit button — full-width, primary variant, `mt-6`
  7. Cross-link — Body typography, centered, `mt-4` ("Already have an account? Sign in" / "Don't have an account? Create one")

### Workspace Layout — D-09, D-11, D-12

- Root: horizontal flex, `h-screen overflow-hidden`
- Sidebar: `w-64` expanded, `w-0` or `w-12` collapsed (transition: `transition-all duration-200`)
  - Top section: "Notely" brand text (`h-12` header, `px-4`)
  - Middle section: "Pages" label + empty state (flex-1, overflow-y-auto)
  - Bottom section: user avatar button (`h-12`, `px-4`, `border-t`)
- Main content: `flex-1 overflow-y-auto`
- Sidebar toggle button: fixed to sidebar edge, `h-11 w-11` touch target

### Workspace Empty State — D-10

- Centered in main content area: `flex flex-col items-center justify-center h-full gap-4`
- Heading: "Welcome to Notely" — Heading typography
- Body: "Create your first page to get started." — Body typography, `text-muted-foreground`
- CTA button: "New Page" — primary variant, `mt-2`

## Interaction Contracts

### Form Loading State — D-14

- On submit: button transitions to disabled + shows `<Loader2 className="animate-spin" />` icon prepended to label text
- Button label during load: "Signing in..." / "Creating account..."
- All form inputs become `disabled` during submission
- Implemented via `useActionState` (React 19) or `useFormStatus` — no custom loading state

### Inline Field Errors — D-13

- Error text appears directly below the relevant `<Input>` with `mt-1` spacing
- Class: `text-sm text-destructive`
- Managed by React Hook Form `<FormMessage>` component
- Server-side auth errors (wrong password, email taken) appear below the email field or as a card-level message above the submit button

### Sidebar Toggle Button — D-11

- The sidebar toggle button is icon-only (no visible label).
- Must declare `aria-label="Toggle sidebar"` on the `<Button>` element to satisfy WCAG 4.1.2 Name, Role, Value.
- Icon: `<PanelLeft />` from lucide-react (or `<PanelRight />` when sidebar is collapsed).

### Sign-out — Claude's Discretion

- Direct sign-out: no confirmation dialog. Click "Sign out" in user menu → immediate `authClient.signOut()` → redirect to `/login`.
- Rationale: Notion and Linear both use direct sign-out. Confirmation dialogs add friction with no recovery value for this action.

### Loading Skeleton — Claude's Discretion

- Workspace layout renders a skeleton on initial load (before session resolves):
  - Sidebar: three `<Skeleton className="h-6 w-40" />` stacked with 8px gaps
  - Main content: two `<Skeleton className="h-4 w-64" />` centered
- Auth pages: no skeleton — rendered server-side, no async shell needed

## Error Copywriting Contract

| Situation | Copy |
|-----------|------|
| Invalid email format | "Enter a valid email address." |
| Password too short | "Password must be at least 8 characters." |
| Passwords do not match | "Passwords do not match." |
| Display name empty | "Enter your name." |
| Email already registered | "An account with this email already exists. Sign in instead." |
| Wrong email or password | "Incorrect email or password." |
| Google OAuth failure | "Google sign-in failed. Try again or use email and password." |
| Network / unexpected error | "Something went wrong. Please try again." |

**Source:** Claude's Discretion (CONTEXT.md grants wording to Claude); error messages are specific, avoid leaking which field is wrong for security-sensitive cases (combined "email or password" message for wrong credentials, per SEC-06)

## Copywriting Contract

| Element | Copy | Pattern Note |
|---------|------|--------------|
| Primary CTA (sign-in) | "Sign in" | Intentional domain-standard exception to verb+noun rule — "Sign in" is the universal convention for authentication entry; adding a noun ("Sign in to account") would be unnatural. |
| Primary CTA (sign-up) | "Create account" | Follows verb+noun pattern. |
| Primary CTA (workspace) | "New Page" | Intentional domain-standard exception to verb+noun rule — Notion, Linear, and similar tools use noun-first labels for creation actions in content contexts; "Create Page" would be grammatically correct but deviates from established user expectation in this domain. |
| Google OAuth button | "Continue with Google" | Follows verb+noun pattern. |
| Auth card title (login) | "Sign in to Notely" | Page heading, not a CTA. |
| Auth card title (register) | "Create your account" | Page heading, not a CTA. |
| Empty state heading | "Welcome to Notely" | Heading, not a CTA. |
| Empty state body | "Create your first page to get started." | Body copy, not a CTA. |
| Sign-in cross-link | "Don't have an account? Create one" | Inline link, not a primary CTA. |
| Sign-up cross-link | "Already have an account? Sign in" | Inline link, not a primary CTA. |
| Sidebar pages section header | "Pages" | Section label, not a CTA. |
| Sidebar pages empty state | "No pages yet." | Status copy, not a CTA. |
| User menu sign-out item | "Sign out" | Menu item convention; imperative verb form is standard for menu actions. |
| Loading (sign-in) | "Signing in..." | Progressive form during loading state. |
| Loading (sign-up) | "Creating account..." | Progressive form during loading state. |

No destructive actions in Phase 1. Sign-out is non-destructive (session is ephemeral).
